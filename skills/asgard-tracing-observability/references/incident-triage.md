# 按 TraceId 排查线上异常

适用于已提供 TraceId、错误请求快照或具体失败请求的场景。先使用已获授权的观测工具、查询服务或目标环境日志读取链路；已有 TraceId 时不要仅凭局部快照要求用户重新提供页面和路径。

## 读取实际请求

1. 核对目标部署版本、环境和时间范围，按完整 TraceId 精确查询。通过 `ITraceQueryService` 读详情，或查目标环境配置指定的独立 Trace 库；它不一定是业务数据库。
2. 同时读取请求方法、路径、状态码、时间、顶层异常字段和完整 `StepsJson`、备注/标签/分支。记录所用时区，避免把 UTC 与服务器/用户本地时间混成同一时间窗口。
3. 若 `ExceptionSummary` 为空，继续看失败步骤及其异常内容。Controller/Service 捕获并转换的异常可能只在步骤中留下线索；数据库日志没有同 TraceId 行也不等于链路没有失败。
4. 将 `IdentitySnapshotJson` 的采集时点与认证中间件、授权过滤器、Controller 执行顺序对齐。入口快照匿名可能早于认证；结合具体路由授权及步骤证据判断，不能据此直接认定 token 无效。
5. 查询范围不足时补查同一时段的容器日志、普通摘要日志、代理请求与相邻请求。保留证据与推断的区别，不把不相关的旧异常当成当前请求原因。

按 TraceId 查询只返回脱敏且与故障相关的字段。不要打印连接串、完整 Authorization/Cookie、token、密钥、用户全量资料，也不要尝试还原 `[REDACTED]`。若直接查库，使用参数化条件，不拼接外来 TraceId 到 SQL。

自动参数摘要不保证所有日志通道已脱敏：string 可能直接采集，复杂对象的 `Code` 也可能是协议凭据。OAuth code/code_verifier/id_token_hint/logout_token、SAML assertion 和密码均按敏感内容处理；业务 Code 只有确认不含凭据时才可摘要。核对目标 sink 对 query、form、嵌套 returnUrl、异常及 Hosting/MVC/代理日志的实际处理，仅输出脱敏摘录。Heimdall 5.5.2 的额外日志/Trace 装饰不能推定为所有 Asgard 应用的默认保护。

## 根据失败步骤定位

- 401/403 先核对实际认证/授权失败步骤；HTTP 500 且业务 Action 已执行时，继续沿具体 Service/Repository 异常查根因。状态和匿名快照都不能替代异常证据。
- 对“列表能查到、按 ID 却未找到”，比较原查询范围与单实体读取的实体归属、软删除、缓存复核和并发变化。列表后 `GetAsync` 不保证等价，详见 [租户查询与快照边界](../../asgard-database/references/shared-entity-cache-tenant-scopes.md#列表与单实体读取的边界)。不要先放宽过滤或修数据库。
- 对回调、刷新或退出异常，先确认 issuer/client/tenant/sub/sid、请求所属会话版本和实际协议错误，再判断失效范围；不要用 OP 最近账号替代原凭据身份。
- 若 `Trace.Enabled=true` 且 `CaptureAllRequest=false`，成功请求通常不持久化。成功回归没有 Trace 行不能当作请求未执行；用实际 HTTP/业务响应、页面结果及必要摘要日志验收。不要仅为一次核验开启长期全量采集。

Trace 属于尽力而为记录：6.0.2 有界队列饱和或重试耗尽可丢弃，结果不明确的数据库提交可能重复。查不到记录时核对存储、保留期限与诊断，不宣称请求一定没有发生。

## 复现与修复

从失败分支提取最小输入、真实数据形状和当时授权范围。在独立测试数据库/schema 或已授权测试租户复现，不直接把生产请求体重放成写操作。

数据库/租户故障的夹具应启用真实租户保护，仓储与 FreeSql 共用身份访问器。仅 mock “返回空”常常掩盖列表与单实体读取的不同契约；相关规则看数据库 skill。

修复原失败路径，覆盖相邻授权与数据边界；不要用全局 catch 返回成功、删合法业务数据、关闭租户过滤或跨租户授权全放行来消除报错。认证状态清理需遵守用户已明确的范围，用户与业务数据不随会话清理删除。

完成报告给出失败请求、具体根因、代码修复、实际回归结果和已验证部署版本。若只通过静态配置或 HTTP 200，不能声称完整业务操作或页面流程通过。

## 已验证的故障形状

Heimdall 5.5.2 修复的平台概览故障：获准跨租户列表包含合法的应用直属空 TenantId 行，逐项单实体读取又执行非空租户归属复核，导致 Service 报“未找到”。异常在步骤中，入口身份快照匿名。修复在已有授权查询快照上共享纯风险评估器，没有修改租户保护或用户数据。

该例用于识别边界差异，不意味着所有空 TenantId 都合法，也不授予详情/写入权限。证据：[5.5.2 发布说明](https://github.com/BenLampson/Asgard.Heimdall/blob/v5.5.2/docs/releases/5.5.2.md)。
